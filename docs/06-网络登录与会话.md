# 06 · 网络、登录与会话

## 1. 默认网络行为

**已确认：不强制直连。** 默认 FollowSystem，应用不主动设置 `Proxy.NO_PROXY`、不绑定到绕过 VPN 的网络、不调用 VPN bypass。系统 VPN 是操作系统路由，不等价于 HTTP 代理配置；“跟随系统”并不保证用户设备上一定存在代理。

首版提供 FollowSystem 和 CustomHttpProxy(host, port, optional credentials)。API、封面、正文、下载、域名检测共用 NetworkProfile。代理不可用时明确报错，不自动降级成直连。SOCKS5、内置 VPN、节点订阅不在首版范围。

切换 Profile 时递增 generation：取消/暂停旧策略请求，重建对应客户端与连接池，重试必须使用新策略。进行中的下载记下断点；旧响应不能覆盖新策略状态。

Android WebView 有自己的网络栈；OkHttp 配置不会自动应用到 WebView。优先使用系统 VPN 路由；自定义 HTTP 代理需检查 AndroidX WebKit `PROXY_OVERRIDE` 支持，在网页登录前完成设置并等待回调。若不支持，明确引导用户使用系统网络方案，不虚构网页登录和 API 已同路由。ProxyController 影响进程内 WebView，网页登录流程必须串行协调。[Android ProxyController](https://developer.android.com/reference/androidx/webkit/ProxyController)

## 2. 地址管理

EndpointRegistry 分开保存 `website`、`api`、`image`、`auth`、`discovery` 候选集合和当前选择。展示地址有来源标签及最近检测结果，不把域名列表当认证凭据。

候选顺序：已成功地址 → 编译内置备用 → 经结构/主机校验的来源发现接口结果。首版按来源协议支持发现，不建立通用脚本下载器。解析规则变化通过 APK 更新交付。

- 首次探测尽量匿名并限制并发；成功标准是预期业务结构，不只是 HTTP 200 或 ping。
- TLS/解析失败、登录失败、配额用尽分别处理；认证错误不会触发所有域名轮询。
- GET/HEAD 在短暂网络故障后至多自动重试两次，指数退避与抖动；429 尊重 Retry-After。
- 登录 POST 不静默切到未验证地址，写操作不自动重复提交。
- API 域名可从发现结果更新，但携带凭据前还要通过来源信任策略。未知新主机只探测，不自动发送密码、Token 或 Cookie。
- 重定向跨 origin 默认剥离认证头，按来源白名单显式决定例外。头像/封面 CDN 不接收不必要的 API 凭据。
- 不采用全局关闭证书校验或强行改 Host/SNI 来解决线路故障。

## 3. 三类凭据必须分开

| 类型 | 例子 | 生命周期 |
|---|---|---|
| 请求签名 | picacg HMAC；JM `token`/`tokenparam` | 根据当前请求和协议版本生成，不代表用户登录 |
| 用户会话 | picacg 用户 token；JM Cookie/JWT；EH Cookie | 由平台认证产生，可能过期或被服务端撤销 |
| 用户 API Key | NH 新实现中的 Key 认证 | 用户提供并验证，不能自行刷新或伪造 |

平台协议中的同名 `token` 不统一成一个字段。EH 的 gallery token 是作品地址标识的一部分，也不能当用户会话。

## 4. 状态机

`Anonymous → Authenticating → Authenticated → Expired/NeedsChallenge/AccessDenied → Authenticating`。

每个来源独立状态；EH 登录成功和 EX 有访问权限是两个状态维度。一个来源过期不清除其他平台账号。对外只发布账号显示名、状态、验证时间与可用操作。

1. 读取本地加密会话，不把“存在 Token”视为认证成功。
2. 首次需要认证时检查有效性；可用缓存允许先展示但标识刷新状态。
3. 业务响应明确过期后，按 source/account 使用 single-flight 锁，最多执行一次恢复。
4. 平台有真实 refresh 能力才调用 refresh；没有则使用用户允许保存的凭据重新登录，或提示用户操作。
5. 恢复成功只重放幂等请求一次；密码错误、网页验证、权限不足不循环自动登录。
6. 退出登录增加 session generation，取消在途认证任务，清理对应 Cookie/Token/WebView 会话；旧请求不得写回新会话。

JM Cookie 路径与 JWT 路径以来源协议版本明确选择，不把旧签名算法和新认证接口随意拼接。NH API Key 和网页登录 Cookie 提取出的 User token 同样分别建模，详见平台规格。

## 5. WebView 登录与自动获取凭据

**已确认：账号管理支持按平台使用 WebView 登录，由 App 自动获取登录会话。** 用户在平台网页完成登录后，无需常规手工复制 Token。此能力按平台实现；Cookie、用户 Token 和 API Key 不能互相替代，也不能从一个网站的会话推导另一个 API 的身份。

### 5.1 登录流程

1. 账号管理选择平台的“网页登录”。创建 `LoginAttempt(sourceId, attemptId, sessionGeneration, networkGeneration)`，保存发起页面；从已验证来源配置取得登录 origin 和允许跳转范围。
2. 先应用当前网络策略，再显示 WebView。页面提示“完成登录后将自动返回”；网页输入由平台页面处理，不额外抓取密码输入框。
3. 来源指定的成功回调、主框架导航或会话变化触发候选检查；`onPageFinished` 仅作检查时机，页面加载完成不代表登录成功。SPA 未跳转时允许有界检测，并提供“我已完成登录，重新检测”。
4. 按来源规则读取所需 Cookie/Token，形成临时 `SessionCandidate`。候选仅留在受限内存中，不写 Room、日志或 UI 状态，也不直接替换当前账号。
5. 用候选创建隔离的验证客户端，请求平台资料或需要认证的轻量接口；明确区分匿名响应、过期、挑战、权限不足和成功。EH 认证与 EX 权限分别检查。
6. 核对本次 attempt、网络 generation 和会话 generation 仍有效，原子提交加密会话与账号描述，再关闭 WebView 并返回发起页面；需要时恢复一次幂等操作。
7. 未获取到凭据则停留登录页；验证失败展示原因并允许重新登录。取消、退出、切换账号或网络后令旧 attempt 失效，迟到回调不得保存会话。重新登录失败或取消，不将尚可用的旧会话直接覆盖成空值。

### 5.2 获取方式与能力边界

| 实测存储/返回位置 | 原生实现方案 | 约束 |
|---|---|---|
| 网站 Cookie，包括网页脚本不可读的 HttpOnly 会话 | `CookieManager.getCookie(verifiedUrl)`，提取来源声明的字段 | 精确匹配可信 URL/字段，不能用 `document.cookie` 替代所有 Cookie |
| 已确认的 localStorage/sessionStorage 字段 | 在可信主框架使用 `evaluateJavascript` 读取指定键 | 仅在该站实测需要时启用；回调时再次核对 origin、attempt 与 generation；不遍历整个存储区 |
| 平台提供的登录回调 | 按其协议验证 state/回调来源，再处理 code/token；需兑换时走平台接口 | 没有协议证据时不发明 OAuth/refresh 流程 |
| 仅在登录 API 响应中返回、网页不保存的 Token | 优先原生登录 API；确有必要时单独设计并测试该站桥接 | 不承诺通用 WebView 抓包；不能假定请求拦截能读取所有响应正文 |

Android `CookieManager` 返回指定 URL 的请求 Cookie 字符串；分区 Cookie 还有顶层分区限制。[CookieManager 官方接口](https://developer.android.com/reference/android/webkit/CookieManager)

`evaluateJavascript` 在当前页面上下文异步执行，并在 UI 线程回调，因此必须约束执行页面和回调归属。这里只使用内置来源声明的固定提取规则，不建立可下载脚本/扩展接口。[WebView 官方接口](https://developer.android.com/reference/android/webkit/WebView)

`shouldInterceptRequest` 是请求处理入口；重定向链只通知初始资源 URL，不能充当读取所有登录响应的抓包器。网页登录流程按实际 Cookie/存储/回调实现，并保留每平台证据。[WebViewClient 官方接口](https://developer.android.com/reference/android/webkit/WebViewClient)

### 5.3 六平台入口基线

| 平台 | 登录入口 | 自动获取策略 |
|---|---|---|
| picacg | 原生账号密码为基线 | 登录 API 返回用户 Token 后验证；尚无证据证明网页登录会话可替代该 API Token |
| EH/EX | WebView 为主要候选，Cookie 导入备用 | 读取相关登录/站点域 Cookie，分别验证 EH 会话和 EX 访问权限 |
| JM | 原生账号密码为基线 | 按已验证协议取得 Cookie/JWT；网页登录与 App API 是否兼容须单独证明 |
| Hitomi | 无需登录 | 不显示虚构的 WebView 登录按钮；挑战验证与账号登录区分 |
| htcomic | WebView 候选、账号密码/导入按实测保留 | 读取当前可信站点会话 Cookie，再确认登录状态 |
| nhentai | WebView 候选，API Key 为另一入口 | 按已研究站点协议从网页会话提取 User token；不能当作 API Key 使用 |

以上是实现与联调基线。只有通过该站测试的登录方法才在 Android 正式版启用。

### 5.4 Cookie 与客户端桥接

- 仅加载对应来源登录/验证页面，允许其明确需要的登录域和重定向域；退出后返回原任务。
- 从 WebView 的 CookieManager 读取来源范围内会话，注入本来源 OkHttp CookieJar；反向同步也是显式操作。
- CookieJar 按域、路径、secure、hostOnly、expiresAt 匹配；不把所有 Cookie 返回给任意请求。
- CookieManager 的 `getCookie(url)` 返回请求 Cookie 字符串，不完整包含所有 Set-Cookie 属性。导入时按已验证 URL/源合同限制范围，不能凭空恢复原始 domain/path/expiry 元数据。
- 不假定系统浏览器/Custom Tabs 的 Cookie 可直接读取。若站点拒绝 WebView，可使用平台支持的官方回调，或由用户手工导入其会话；不宣称能自动同步外部浏览器登录。
- WebView 同一 profile 的同域 Cookie 不天然按账户隔离；首版每来源单活动账号，切换时定向清理，EH/EX 作为同一账号组协调。
- UA、验证 Cookie 与网络出口应一致；出口变化后挑战可能需要重做。完成挑战后仍验证真实接口，不把检测到 `cf_clearance` 当成登录成功。

参考：[CookieManager](https://developer.android.com/reference/android/webkit/CookieManager)。

## 6. 保存与脱敏

会话采用 Android Keystore 管理 AES-GCM 密钥，密文存在应用私有且排除系统备份的目录。哔咔、JM、绅士漫画原生登录页提供“记住账号密码（加密保存）”，默认勾选；点击登录后，在等待网络配置、探测和认证之前，先将账号密码写入独立的 `login-input.<source>` 加密记录。成功、密码错误、网络失败或随后取消均保留本次提交；再次进入页面或重启应用后优先填充该记录，没有时兼容读取旧账号密码。填写记录不能作为已验证会话，也不参与后台自动恢复或手动账号备份；失败重登保留原会话及其恢复密码。密码默认隐藏，支持显隐切换和一键清空；回填只读取当前来源，不覆盖已编辑或清空的内容；修改账号时清空密码。页面退到后台时清空明文密码，返回后恢复当前账号匹配的已保存密码并隐藏。取消勾选不保存本次输入，成功登录后删除此前记住的密码和填写记录。“忘记已保存的密码”和“清除本地账号”均删除填写记录；导入账号时清除旧填写记录，改用导入的账号密码。旧版只有会话的账号需重新输入密码并点击登录一次。

哔咔、JM、绅士漫画在启动和需要读取内容时优先恢复已保存的 Token/Cookie；有效会话直接复用，不重复提交密码。只有明确会话过期、当前可信线路无法使用原 Cookie，或此前只剩已保存密码时，才自动使用已记住的账号密码登录一次；验证成功后加密保存新会话，并至多重放一次原读取请求。JM 的请求签名 `token` 仍按协议生成，不能替代账号 Cookie。

启动、阅读及下载共享每来源一次恢复任务。网络故障、限流和权限问题保留会话并显示实际原因，不把它们当成密码失效。密码错误、需要人工验证、或恢复后再次过期会停止自动尝试；用户仍可点击“使用已保存账号登录”或“验证当前会话”主动重试。“忘记已保存的密码”保留当前有效会话；“清除本地账号”删除会话及账号密码，并阻止迟到的恢复结果重新登录。重新验证同一账号时保留记住的密码，替换账号不得继承旧账号密码。

哔咔一键注册在请求前将完整生成资料加密保存为独立记录，服务器确认成功后保存待验证的账号密码，再自动登录及验证会话。网络结果不确定时复用同一份资料，先尝试登录确认是否已注册；不会自动换账号反复注册。注册后的登录被限流不丢失凭据，下次可恢复。HTTP 400 / 错误码 1023 按限流显示，不能误报密码错误。用户主动复制时输出完整账号、生日及三组密保资料；资料面板防截屏，退到后台关闭，系统剪贴板标记敏感内容。忘记密码或清除账号同时删除注册资料。详见 [一键注册](30-哔咔一键注册与自动登录.md)。

新版本地导出使用用户设置的备份密码加密整个 `.picomic` 文件，可选择包含平台会话和记住的账号密码。导入先解密和预览，再逐来源选择账号；默认不覆盖已有本机账号。导入的会话为待验证状态，重新使用本机 Keystore 加密；密码独立于设备密钥，可跨设备恢复。普通 JSON/WebDAV 同步仍不包含平台凭据；代理口令、WebDAV 密码始终排除。格式与验证见 [加密配置与账号备份](25-加密配置与账号备份.md)。

日志仅记录 sourceId、请求类型、host、HTTP 状态、耗时、错误类别和脱敏 traceId。禁止响应正文中的令牌、Cookie、密码、完整认证 URL 写日志。用户主动导出诊断前可查看内容。退出登录清理会话，不默认删除已下载作品。[Android Keystore](https://developer.android.com/privacy-and-security/keystore)

## 7. 必测场景

系统代理、VPN、分应用 VPN、代理断连；API 成功但图片失败；WebView 与 API 出口不同；并发 401；登录取消/退出登录期间旧请求返回；账号切换；Cookie domain/path/expiry；跨域重定向；EX 无权限；NH Key 撤销；JM 协议不兼容。

自动获取专项：HttpOnly Cookie、页面存储式 Token、SPA 不跳转、仅完成挑战但未登录、凭据缺失/验证失败、候选不覆盖旧会话、跨域页面禁止读取、取消/换网后的迟到回调、关闭后不遗留检测任务、成功后回到正确发起页。

这些属于 Android 联调验收；HTML 中的“已连接/登录成功”均是显式标注的演示反馈。

## 设置中的凭据与网络边界

WebDAV 使用独立凭据及网络客户端，遵循用户代理策略，不发送漫画平台 Cookie/Token。主机配置变化需校验来源并重新验证相关会话，不能直接向新域转发旧凭据。EH“忽略警告”只作用于允许跳过的站内内容提示，不能跳过 TLS、认证和权限错误。自动打卡仅在有效会话和用户启用时执行。详见[设置规格](12-设置与偏好规格.md)。
