# 账号会话自动恢复与验证

2026-09-22。修复保存了账号密码后，探索页仍反复要求登录的问题。

## 原因与处理

原实现已加密保存 Token/Cookie 和用户勾选记住的账号密码，但启动恢复只验证旧会话；验证失败后未尝试已保存密码。内容请求只接受 `AUTHENTICATED` 状态，遇到过期则清除失效会话并直接报错，没有恢复和读取重试。JM 切换 API 线路后，Cookie 的 origin 校验失败也直接要求用户登录。

- 哔咔、JM、绅士漫画共享每来源 `PasswordSessionRecovery`，独立于页面生命周期。启动、阅读和前台下载使用同一个恢复任务。
- 优先验证保存的会话；已认证时直接复用。明确过期或当前可信线路无法使用原 Cookie 后，用已保存密码登录一次，再独立验证并加密保存新会话。只有保存密码、没有会话的旧记录也能恢复。
- 内容层只重放一次原读取操作，不重复签到或其他写操作。新旧账号分区不一致、退出账号或切换网络时，不将旧请求重放到另一账号。
- 并发过期共用一次登录。密码错误、权限拒绝或恢复后再次过期会停止自动尝试；用户主动验证或登录可重试。网络故障、限流、解析变化不触发密码登录，也不会因此删除尚未证实过期的会话。
- JM 使用账号 Cookie；协议的请求签名 `token` 仍逐请求生成，不作为账号会话保存。切换线路不转发旧 Cookie，仅在当前已信任且协议探测通过的线路登录。
- 不改变凭据存储格式、备份格式或导航。密码、Token/Cookie 不进入 UI 状态或日志，临时凭据在操作结束后清空。

## 验证

- JVM：104 项通过，包括新增 12 项恢复场景；覆盖冷启动复用、密码恢复、新会话保存、并发合并、错误停止、网络重试、无密码、权限拒绝、退出、换网和单个等待页面取消。
- Android：49 项不同用例最终通过。新增 9 项使用本地 MockWebServer 和真实 JM 编解码、Cookie、加密存储、内容适配器的恢复测试；新增 2 项探索页测试确认恢复后直接显示安全测试作品，密码错误后才显示管理账号入口。其余回归覆盖原有登录、网络、JM/绅士漫画内容、备份和页面导航。
- 首轮新增探索页测试在 `runBlocking` 中等待 Compose 重组而超时；改为 Compose 测试规则的 `waitUntil` 后通过，未改动产品逻辑或降低断言。
- 后台模拟器 API 36.1，使用 `-no-window`，进程 `MainWindowHandle=0`。所有新增网络测试只访问本地测试服务器；页面仅使用合成作品信息和本地测试插画，没有在办公桌面显示漫画页面。
- 本地日志：`artifacts/session-recovery-build-final.log`、`session-recovery-android-tests.log`、`session-recovery-ui-tests.log`、`session-recovery-ui-retest.log`。这些属于模拟环境验证，未使用用户的真实平台账号或实体手机。
- 本地正式签名 Release 构建通过，Release lint 为 0 errors、49 warnings、1 hint，6 项发布脚本测试通过。无窗口模拟器完成 v0.3.4 到本地 v0.3.5 的覆盖安装，深色主题和跳过详情页设置保留，未记录崩溃。
