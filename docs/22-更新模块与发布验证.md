# 更新模块与发布验证

2026-09-20，applicationId `io.github.ddmoyu.picomic`。开发默认版本仍为 `0.3.0-alpha`；标签发布通过构建参数生成稳定版本。

## 已实现

- `ddmoyu/PiComic` 已按用户要求改为公开仓库，同时分发源码与 Releases。构建参数 `releaseOwner`、`releaseRepo` 默认使用该仓库；App 不包含 PAT，不要求登录 GitHub。
- 最新稳定 Release、版本整数比较、同次发布的清单及 APK 绑定、ABI/minSdk、大小与 SHA-256 校验。GitHub API 固定版本 `2026-03-10`，依据[官方发布 API](https://docs.github.com/en/rest/releases/releases)。
- 更新备用线路默认开启，可在“设置 → 更新”关闭。优先 GitHub；网络失败、403/429 限流或服务器错误时，API 尝试 GH-Proxy，清单和 APK 依次尝试 GH-Proxy、GHProxy.net。官方 404 表示尚无发布，不当作最新，也不反复请求镜像。
- ETag 按线路复用；API 和文件下载分别持久化每条线路的冷却时间。GitHub API 被限流不阻塞备用线路或文件下载；切换网络配置立即终止旧请求。
- 下载独立存入私有 `updates` 目录，强 ETag 与精确 Range 恢复。不同线路使用不同的断点身份，切换时重下，避免混合分片；重新取得原 Release 身份后才恢复任务。
- 仅允许已配置的 HTTPS GitHub / 镜像地址及受信 CDN 跳转，不向更新服务发送平台 Cookie、Token 或 GitHub 凭据。镜像只承担传输，最终仍验证仓库、发布、清单、APK 大小/摘要/包名/版本/ABI 和已安装应用的证书集合。
- 下载状态持久化；回到后台暂停，前台由用户继续。重启后核对任务与完成的 APK；取消仅清理更新任务。
- 用户主动安装才请求“允许安装未知应用”；FileProvider 与临时读取授权交给系统。唤起安装器不视为成功，下次启动读取实际已安装版本并清理旧任务。
- 可选冷启动检查默认关闭，24 小时间隔，只显示非阻塞提示，阅读时延后，不自动下载/安装。

## 资产生成

`tools/prepare-release.ps1` 读取最终签名 APK，核对包名、版本、非调试构建、ABI、minSdk、v2 签名与预期证书，生成 `picomic-update.json` 和验证报告。默认拒绝 alpha/beta 等开发版本；本地开发验证需显式指定 `-AllowDevelopmentBuild`。该工具本身不发布。

`tools/ci-release.py` 校验精确 `vX.Y.Z` 标签与版本编码，读取更新说明，复核资产后生成摘要。Actions 创建 Draft、上传、逐个读回对比，再转为稳定 Release。已发布版本不被覆盖，错误版本需使用更高标签修复。
