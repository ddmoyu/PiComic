# 更新模块与发布验证

2026-09-20，开发构建 `0.3.0-alpha`，applicationId `io.github.ddmoyu.picomic`。

## 已实现

- 构建参数 `releaseOwner`、`releaseRepo` 指定独立的公开 GitHub Releases 渠道。默认留空；当前源码仓库仍为 private，应用不包含 PAT。
- 最新稳定 Release、版本整数比较、同次发布的清单及 APK 绑定、ABI/minSdk 匹配、大小与 SHA-256、ETag 条件请求和限流冷却。GitHub API 固定版本 `2026-03-10`，依据[官方发布 API](https://docs.github.com/en/rest/releases/releases)。
- 下载独立存入应用私有 `updates`，不属于图片缓存或漫画下载。强 ETag 与精确 Range 恢复；每次继续先读取原 Release 身份，重新走 GitHub 受信 HTTPS 跳转获取短期 CDN 地址。
- 下载状态持久化；回到后台暂停，回到前台由用户继续。进程重启重新解析任务、核对已完成安装包。取消只清理更新任务。
- APK 校验包含摘要、包名、版本名/整数版本、minSdk、实际 native ABI 与当前已安装证书集合。最终签名有效性及覆盖安装由 Android 安装器验证；首版不接受远端声明的签名轮换。
- 用户主动安装才请求“允许安装未知应用”，返回后重新检查权限；FileProvider 与临时读取授权交给系统。显示等待系统处理，绝不把唤起安装器当作安装成功。下次进程启动以系统已安装版本判断并清理旧任务。
- 可选冷启动检查默认关闭，持久化 24 小时间隔，只显示非阻塞提示；阅读时延后提示，不自动下载或安装。

## 构建与资产准备

正式发布构建应配置真实公开分发仓库及正式签名；示例中的占位值需替换，不能使用私有仓库作为匿名渠道：

```powershell
.\gradlew.bat :app:assembleRelease -PreleaseOwner=发行账号 -PreleaseRepo=公开分发仓库
```

`localReleaseSigning=true` 仅为本机开发签名的 R8 验证，不代表正式签名。普通 Release 保持未签名，禁止将密钥或口令提交到 Git。

最终签名 APK 使用工具读回元数据及签名，自动生成清单并再次核对复制文件摘要：

```powershell
.\tools\prepare-release.ps1 -Apk 路径\已签名.apk -ExpectedSignerSha256 正式证书的64位SHA256
```

工具默认拒绝 debuggable 和 alpha/beta 等开发版本。本地测试可显式加 `-AllowDevelopmentBuild`；验证报告标明开发构建。工具不上传、不创建或发布 Release。

发布按 11 号合同：更高版本号、完整简洁发布说明，创建 Draft，上传 APK 与 `picomic-update.json` 后逐一读回检查，再发布稳定版。源码仓库无需转公开。

## 外部验收仍需具备

正式签名、实际公开分发仓库、真实稳定发布资产、实体手机的权限拒绝/撤销、安装取消/失败/成功和旧版覆盖数据保留。当前不会自行创建正式密钥、公开私有源码或发布未经验证的版本。
