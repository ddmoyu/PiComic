# 内容接入与 JM 验证

更新：2026-09-20。当前开发版 0.3.0-alpha；这是持续开发记录，不是六来源全部通过的准入结论。

## 已实现

- 真实内容模型采用来源、作品字符串 ID、实际章节 ID 和页 ID，搜索分页取消过时请求并去重。
- 哔咔搜索、分类、详情、完整章节/页面分页接入同一会话验证链路。真实内容进入本地收藏、历史和三种阅读模式；账号/网络变更使旧请求失效。
- 默认 App 读取真实来源。原创示意目录仅在显式开启 Debug 演示开关时使用，Release 无该入口。
- JM 使用独立 `jm-cookie-1.8.2-v1`：每请求时间、签名和 AES 响应解码绑定；没有混用 2.x JWT profile。
- JM 匿名分类/搜索/详情/章节、原生登录候选、独立资料验证、加密 Cookie、会话恢复和来源隔离。已有会话失效不会悄悄退到匿名身份。
- JM 图片处理读取章节页面中的 photo/scramble 参数，保留文件名和算法版本。原尺寸完成条带重排后原子提交缓存，再交给 Coil/阅读器；GIF 和已还原图片不重复处理。
- API 可信候选选择与匿名可用性检测；图片分流通过 setting 独立解析，换 API 不能把旧线路 Cookie 转发过去。
- 持久本地收藏、阅读历史、按来源搜索历史；未知来源行保留在数据库，展示已知来源时不使整张书架失效。

## 实测范围

Windows 上以当前显式 HTTP 代理、正常 TLS、匿名请求核对 JM：setting、categories、空结果 search、categories/filter、album、chapter、chapter_view_template。只保留字段、计数和协议参数，不保存作品正文、封面或平台图片。

setting 返回 1.8.2；列表一页 80 项；全册没有 series 时使用稳定 `whole`；chapter ID 与请求 photo ID 一致；页面模板提供匹配的 aid 与 scramble 参数。具体作品、标签和页 URL 不进入验证文档。

D2 全量：JVM 36 项通过；模拟器 41 项常规测试通过，显式联网测试 1 项未启用；Debug 构建、Lint 通过。JM 首轮定向回归：JVM 总计 41 项、模拟器 11 项通过，包括并发响应使用各自时钟、编码、全册、错误元数据、Cookie 原点隔离、跳转/限流和合成图逐像素重排。新增阅读显示偏好和数据库升级回归继续执行，最终结果记录在完整清单。

首轮验证没有使用真实 JM 账号，后续登录实测补充如下。真实哔咔账号、首中末真实图片、实体手机和下载离线验收仍待执行。

## JM 登录问题修复（2026-09-20）

用户反馈登录提示“JM 响应格式发生变化，请等待来源更新”。实测 `/setting` 的默认 `img_host` 已变为 `https://cdn-msp12.jmdanjonproxy.xyz`，图片分流 1 返回 `https://cdn-msp2.jmdanjonproxy.vip`；分流 2、4 仍返回 `jmapiproxy3.cc`、`jmapiproxy1.cc` 下的 CDN。旧白名单仅支持 `jmapiproxy[1-4].cc`，登录前的 API 探测也执行图片域名校验，因而在发送登录请求之前失败。新增白名单回归用例在旧实现上复现失败。

修复内容：

- API 探测仍验证响应解密和 1.8.2 协议版本，图片线路改由内容请求独立验证，不再阻断登录或会话恢复。
- 图片白名单补充已实测的 `cdn-*.jmdanjonproxy.vip`、`cdn-*.jmdanjonproxy.xyz`，继续拒绝 HTTP、非标准端口、附加域名后缀、用户信息和额外路径参数；旧线路继续兼容。
- 没有改动账号 POST 编码、Cookie 原点隔离或独立账号验证要求，没有引入 JWT 与 Cookie 协议混用。

验证结果：

- Windows 通过显式代理及正常 TLS 实测 POST `/login` 成功；同一 Cookie 的 GET `/login` 返回相同账号身份，确认独立验证接口有效。
- Android 16 模拟器使用 App 的 `JmClient`、`PasswordAccountController`、`SessionCoordinator` 和 Android Keystore 完成真实登录、独立验证、加密保存，再通过新客户端读取加密会话并验证成功。本轮会话恢复在同一测试进程中进行，不等同于实体手机重启验收。
- 凭据通过一次性 ADB 回环通道仅在内存传入；未写入测试源码、命令行参数或诊断输出。测试结束后删除隔离的加密会话和测试密钥。没有访问漫画图片、收藏或执行签到。
- JVM 59 项通过；Android 8 / API 26 和 Android 16 / API 36 各 10 项 JM 回归通过，另有 1 项 Android 16 真实登录验证通过。覆盖新旧图片域名、域名伪装拒绝、图片线路未知/缺失时登录与恢复、协议版本不匹配拒绝、Cookie 原点隔离及既有内容解析。
- `lintRelease`、正式签名 arm64-v8a Release 构建和发布资产本地校验通过；安装包仍为本地 0.3.0 候选，本次不创建版本标签或 GitHub Release。
