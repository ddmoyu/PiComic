# 05 · 六平台接入规格

## 1. 统一约定

本章为实现合同与待联调清单。所有 URL/路由例子来自[固定源码](evidence/source-index.md)，不是平台官方稳定性承诺。主机默认值在接入实测后确认，正文不发布长期有效凭据或签名密钥。

来源 ID 固定为 `picacg`、`ehentai`、`jmcomic`、`hitomi`、`htcomic`、`nhentai`。EX 是 ehentai 的站点模式；作品 ID 必须保留必要 token/版本标识。无章节作品建立稳定 `whole` 全册章节。

## 2. 能力与认证矩阵

| 来源 | 获取方式 | 会话/签名 | 地址策略 | 特殊图像 |
|---|---|---|---|---|
| picacg | JSON API、章节图片分页 | 用户 token + 每请求签名 | API 与图片主机分开 | 普通图片，保留原尺寸信息 |
| EH/EX | HTML + gallery API + 图片页 | 论坛/站点 Cookie，EX 额外权限；gallery token 非账号 token | EH/EX 显式选择，图片域随页解析 | 额度、失效地址、原图能力 |
| JM | JSON/加密响应 + 章节页面元数据 | profile 对应请求签名；Cookie 或 JWT 待协议确认 | API 候选发现与图片分流独立 | 条带重排，格式例外 |
| Hitomi | 元数据 JS、索引、gg.js | 参考代码匿名，图片请求 Referer | 动态 hash/CDN 规则 | WebP/AVIF 等格式需真机验证 |
| htcomic | HTML、阅读页图片数据 | 用户登录 Cookie；匿名能力需逐操作验证 | 内置候选 + 发布页发现 | 图片页防盗链 |
| NH | 近期 API v2，网页兼容待测 | API Key 或网页登录 User token/会话 | API、封面、正文主机分别配置 | 页面格式映射/下载权限 |

六组都提供详情、章节/全册与阅读接口；实际不支持的排行、收藏、账号方法通过 capability 隐藏。登录需求按“操作”判定，不能用一个 requiresLogin 禁掉整个平台所有页面。

## 3. picacg

- 路径证据：`auth/sign-in`、`comics/advanced-search`、`comics/{id}`、`comics/{id}/eps`、`comics/{id}/order/{epId}/pages`（VEN-PICA）。
- 签名器输入包括 method、相对 path/query、时间与 nonce；按协议精确规范化，禁止先签名再改变 URL 编码。
- 登录成功读取用户 token，写入加密 SessionStore，调用资料/轻量认证接口确认状态；认证失败不反复尝试密码。
- 章节/页面必须取齐分页，保留顺序；封面和正文图片请求不能无条件附加 API token。
- 待测：有效 API 主机、app header 版本、登录业务码、章节分页、原图/压缩图行为、时钟偏差错误。

## 4. e-hentai / exhentai

- 搜索/列表读取 HTML；作品地址保存 gallery ID 与 gallery token；必要元数据可走 `api.php`，图片需要从缩略图页/图片页逐步取得。
- 登录采用受控 WebView 和手动 Cookie 导入两种候选；导入字段最少化，逐项校验。EH 与 EX 所需 Cookie 以验证结果为准，不能仅看是否有 `igneous`。
- EX 验证失败返回 AccessDenied，保留 EH 会话，提供用户切 EH 的操作；不能自动把作品原站悄悄替换。
- 图片链接惰性解析，少量预读；额度不足立即停止预取和相关下载，不多线程重试刷额度。
- 待测：论坛登录转站流程、EX 权限、图片额度报错、图片 URL 失效恢复、图库分页、画廊删除与版本变化。

## 5. jmcomic

- 路径样本：`login`、`search`、`album`、`chapter`、`chapter_view_template`、`favorite`。
- `JmProtocolProfile` 绑定接口服务族、版本头、签名规则、响应解码、会话类型、图片规则版本。不能混合 JM-TOKEN 与 BZ-JM-CLIENT 的不同输入规则。
- 每次请求生成一致的时间参数；相应响应解码使用该请求的时间和 profile，避免并发时取错上下文。
- Cookie/JWT 为用户会话；协议 `token` 通常是请求认证材料。若响应返回新 JWT，原子更新并校验 session generation。
- 图片重排独立于 JSON 解码。PageRef/处理元数据保存 photo/episode ID、scramble ID、文件名及算法版本；后台处理后写原子文件再显示。
- 域名发现得到候选集合，验证后选择；图片分流与 API 不强制同域；普通用户看到“API 线路/图片线路”。
- 待测：当前可用 profile、登录错误与过期、域名发现结构、章节元数据、条带重排余数、无需重排图片、GIF/已还原文件。

## 6. hitomi

- `galleryinfo`/索引等元数据不是标准通用 REST；需要专用解析器。搜索索引可能涉及 Range 读取与分页，不在首页下载全量索引。
- 图片地址按文件 hash 和 gg.js 动态规则构建；缓存规则与其版本/获取时间，失效时允许受限刷新再试一次。
- 不建立虚构登录入口；账号页展示“无需登录”。若后续站点行为变化，以验证后的 capability 更新。
- 不把远端 JS 任意执行等同于支持解析；首版解析所需数据/规则子集，遇到不支持结构返回 ParseChanged。
- 待测：索引查询、规则变化、Referer、AVIF/WebP/超大图解码、过期 CDN、Range 不支持时的降级。

## 7. htcomic（绅士漫画 / wnacg）

本需求按 PicaComic 的 `HtmangaNetwork` 对应站点家族解释。Venera 的 `hcomic.js` 指向另一站，不能仅因名称相近拿来替代。

- 历史路由样本为 `photos-index-page-...`、`photos-gallery-aid-...`、`users-check_login.html`；Breeze 新实现同时包含搜索与发布页候选发现。
- HTML 用 Jsoup 结构解析，嵌入图片列表单独处理；不依赖整页一个贪婪正则。
- 会话按当前可信 origin 隔离。站点更换后重新验证登录范围，不把 Cookie 任意改域传播。
- 待测：准确站点家族、发布页真实性、当前搜索路由、匿名可读范围、登录响应、图集分页、图像 Referer。

## 8. nhentai

- 优先验证近期实现的 `/api/v2`，避免只翻译已归档 PicaComic 的旧 HTML 选择器。
- `ApiKeySession` 使用平台用户提供的 Key；`WebSession` 由网页登录产生会话，Venera 参考从 Cookie 提取 User token。两者的权限、生命周期和错误分别记录。
- API Key 非必然免费/人人可得；界面提供相应说明与验证，具体可读/下载范围以账号实际能力决定。
- 不在接口出错时盲目切换 Key、User、匿名三个身份。用户选择的认证方式明确，业务码识别后提示对应恢复动作。
- HTML 兼容读取只有在独立验证后启用；挑战页引导用户完成验证，不声明稳定绕过。
- 待测：v2 搜索/详情/页列表合同、Key/User 认证权限、网页 Cookie 名称变化、验证码、图片服务器规则、下载能力与阅读能力差异。

## 9. 来源准入记录

每来源都需填写：profile 版本、参考提交、验证时间、系统/代理配置、匿名/登录结果、搜索/详情/页列表/首中末页、分页、过期恢复、速率/额度行为、已知限制。通过矩阵才显示“已接入”；开发演示数据只能出现在明确的 Debug 夹具中，Release 不提供伪造成功结果。
