# D1 网络与认证基础

2026-09-20，`0.2.2-alpha`，versionCode `6`。

按开发计划，在阅读器之后推进统一网络与认证基础。本轮完成可运行的代理设置与核心合同；漫画目录仍是原创示意内容，六来源的真实登录和内容接口尚未开放。

## 用户可见变化

- “设置 → 设置代理”支持跟随系统、自定义 HTTP 代理、可选用户名与口令；校验主机和端口，保存后生效，重启后恢复。
- “测试已保存的连接”实际请求 `https://api.github.com/zen`，显示成功、HTTP 状态或连接失败。它仅证明该 HTTPS 地址的可达性，不代表漫画来源可用。
- 不可用的自定义代理不会自动降级直连。尚未保存的编辑不会改变当前连接方式。
- 删除原生页面的“体验演示登录状态”；账号页按平台显示接入状态，Hitomi 保持无需账号。
- 关于页链接到 `ddmoyu/PiComic` 私有仓库及其 Issues；访问需要 GitHub 仓库权限。没有内置 GitHub 凭据，也没有将私有仓库当作匿名更新接口。

旧版本代理字段只是 UI 演示偏好，本轮不会自动启用它们。请在新代理页保存一次配置。已有书架、阅读历史和阅读偏好保留。

## 工程行为

| 部件 | 已实现的边界 |
|---|---|
| NetworkEngine | 跟随平台 ProxySelector/VPN；自定义 HTTP 代理；有限代理认证；更改配置递增 generation、取消旧调用并释放旧连接池；保留的旧客户端不能继续发起请求 |
| 来源客户端 | 独立 CookieJar 和精确 origin 集合；拒绝越界地址；重定向返回给来源适配器处理，不自动转发认证信息；不自动重放失败的登录 POST |
| CookieJar | 按域、hostOnly、path、secure、过期时间匹配，限制内存条数；来源之外的请求不携带会话 |
| 图片 | Coil 的网络加载器已接入同一动态 Call.Factory；现有本地图片继续使用原路径。未来来源图片的身份分区和 PageRepository 在真实来源阶段实现 |
| SecretStore | Android Keystore AES-256-GCM；随机 IV；记录键作为 AAD；AtomicFile 原子写入；密文存于 noBackupFilesDir；损坏/换键不降级为明文 |
| SessionCoordinator | 候选会话和正式会话分离；验证成功后原子保存；检查 attempt、网络及会话 generation；取消、退出、换网后的迟到结果无效；失败的重新登录保留旧会话；恢复磁盘记录只标记待验证 |
| 受控 WebView | 进程级串行使用代理；等待 ProxyController 回调才进入页面；HTTPS/origin 限制；文件/content 访问、第三方 Cookie 和混合内容关闭；证书错误终止；无 JS 密码抓取或原生桥 |
| Cookie 获取 | 从声明的可信 URL 读取指定 Cookie，支持 HttpOnly；页面完成只触发检测；有界轮询和手动重检；候选必须再经来源验证，挑战 Cookie 本身不算登录 |
| 网页生命周期 | 换网取消网页登录；释放 WebView 和轮询；按合同声明的 Cookie 域/路径清理并删除对应网页存储；不会全局删除其他来源 Cookie |

敏感值只存在临时输入、受限网络/认证上下文及密文中，不写 UI 的 StateFlow、普通 SharedPreferences、Room 或诊断记录。代理表单口令不进入 `rememberSaveable`。重填代理时空用户名和口令表示移除认证，页面有明确提示。

## 尚未开放的能力

- 六来源的 `WebLoginSpec` 和真实接口验证器均未启用；不猜测登录 URL、Cookie/存储键或协议版本。
- 带认证的自定义 HTTP 代理可用于 OkHttp；网页登录暂时明确拒绝这种配置，因为通用 WebView HTTP 认证回调不能作为安全、可靠的代理凭据分发依据。建议使用系统 VPN/代理或无认证的 HTTP 代理。
- WebView 不支持 `PROXY_OVERRIDE` 时，自定义代理网页登录会被阻止，不用直连假装同路由。
- localStorage Token 的站点专用提取、EH/EX 权限检查、来源发现、签名、401 single-flight 恢复、退避和 Retry-After 在真实协议适配阶段实现；本轮不提供虚构 refresh。
- 真实代理/VPN 设备组合、平台登录和实体手机尚待联调。Debug 的本地明文例外仅用于 localhost、127.0.0.1 和固定测试主机；Release 不含这些例外。

## 验证

验证命令：

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleDebugAndroidTest
.\gradlew.bat :app:connectedDebugAndroidTest
```

本机首次解析新增依赖时，需要通过本次命令的 Java HTTP/HTTPS 代理参数使用现有代理；没有将本机代理地址写入项目或全局 Gradle 配置。

最终验证通过：

| 检查 | 结果 |
|---|---|
| JVM 单元测试 | 19 / 19；其中网络 8 项、会话 5 项、原有目录及阅读数学 6 项 |
| Android 仪器测试 | 23 / 23，0 跳过；新增网络/认证 4 项、代理设置 1 项，保留阅读控制、长图、数据库、Tab 与导航回归 |
| Lint Debug | 0 错误、17 警告；依赖版本、targetSdk、既有 UI/KTX 约定及备份/ABI 提示，无 baseline 隐藏错误 |
| Debug 构建 | 通过；交付 APK 与测试构建 SHA-256 一致 |
| 模拟器 | Medium_Phone_API_36.1，Android 16；未使用实体手机 |

新增原生检查证明：Keystore 密文可恢复、随机 IV、篡改和换记录键会失败；OkHttp 与 WebView 请求均经过同一个本地代理；HttpOnly Cookie 自动检测及关闭后定向清理；换网销毁网页登录；非法端口不生效，关闭的代理返回失败。

测试使用本地 HTTP 服务、自制网页登录页和测试凭据，不连接漫画平台、不导入真实账号。核心验证日志：`artifacts/d1-network-final-validation.log`。JVM 报告位于 `app/build/reports/tests/testDebugUnitTest/`，设备报告位于 `app/build/reports/androidTests/connected/debug/`。代理失败界面截图（历史截图已清理）。

本轮同时修正测试隔离：UI 流程明确恢复连续阅读基线；本地 HTML 登录夹具声明可信 history URL，避免被按 `about:blank` 拒绝。阅读控制复测发现旧 Compose 测试调度下的快照冲突，受影响测试采用官方 v2 队列调度，保留原有行为断言；应用阅读控制逻辑未作修改。调整后完整 23 项回归通过。
