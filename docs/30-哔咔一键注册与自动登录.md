# 哔咔一键注册与自动登录

## 已确认的交互

保留现有账号密码登录。仅哔咔增加“一键注册”，全程无需填写；账号、独立随机密码、昵称和三组密保信息由应用生成，生日按用户确认的网页规则使用注册当天往前 20 年（生成的注册资料，不代表真实生日）。注册完成后回填账号密码，结果面板列出完整资料并提供“一键复制”，同时自动登录、验证账号；后续启动复用有效会话，过期后使用加密保存的密码恢复。

生成资料在注册请求发出前加密落盘。超时、退出页面或后台中断不会丢失资料；再次操作使用同一组账号，先核实结果，不自动生成另一个账号。服务器明确注册成功后，即使随后的登录被限流，也保留注册资料和待验证账号。已有本地账号时不直接注册替换，先由用户清除本地账号。

注册资料可在登录页查看，密码默认隐藏；复制资料由用户主动点击。资料包含生日和密保信息，存放在 Android Keystore 加密文件中，不进入日志、普通偏好、系统备份或 WebDAV。删除已保存密码或清除本地账号时同时清除注册资料。现有加密账号备份继续保存已注册账号的登录凭据，注册附加资料的跨设备备份不纳入本次范围。

## 已核实的接口

- 当前注册页面脚本仍提交 `POST https://picaapi.picacomic.com/auth/register`；参数为 `email`、`password`、`name`、`birthday`、`gender`、三组 `question` / `answer`。成功响应业务码为 200。
- 现有客户端按相同签名协议调用该接口。生日按当前网页一键注册规则及用户要求自动生成；性别使用协议支持的 `bot`，不推断用户性别。
- 新账号使用 SecureRandom，账号和密码独立生成，不采用网页中账号密码共用随机前缀的方式。
- 实测登录接口会返回 HTTP 400、业务错误 `1023`、`too many requests`；应归类为限流，不显示账号密码错误，也不自动重发注册或登录请求。

证据：2026-09-24 只读检查的 [注册页面](https://manhuabika.com/pregister/)、其公开脚本 `assets/js/index-ea_4Germ.js`，以及 [Pica 注册请求](https://github.com/fanyuecheng/Pica/blob/main/Pica/Login/Request/PCRegistRequest.m)。只读研究不代表本轮已在真实平台创建账号。
