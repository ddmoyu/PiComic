# 03 · 技术架构与工程规范

## 1. 架构决策

PiComic 独立使用 Kotlin 原生 Android 技术栈。应用内直接访问六个平台；首版无需自建内容中转服务。来源逻辑静态编译进 APK，保留内部接口以隔离差异，不引入扩展执行环境。

| 层 | 建议选型 | 职责 |
|---|---|---|
| UI | Jetpack Compose + Material 3 | 页面、主题、底部面板、布局 |
| 状态 | ViewModel + StateFlow + Coroutines | 单向事件/状态流、生命周期取消 |
| 导航 | AndroidX Navigation Compose 稳定版本 | 路由、返回栈、阅读参数 |
| 网络 | OkHttp；稳定 JSON API 可使用 Retrofit | 网络策略、认证、重试、取消 |
| JSON/HTML | kotlinx.serialization + Jsoup | DTO 与站点结构解析 |
| 图片 | Coil 3 + ZoomImage 的 Coil 3 适配 | 图片加载、缩放、局部解码 |
| 存储 | Room + DataStore + Android Keystore | 业务数据、偏好、会话密文 |
| 下载 | 持久队列 + 前台执行器/系统任务调度 | 主动下载、恢复与通知 |
| 注入 | 初期显式构造/AppContainer | 小规模依赖易理解，必要时引入 Hilt |

这是选型基线，不锁定未经构建验证的具体版本。建工程时统一验证 Kotlin、AGP、JDK、Compose BOM、Coil 与 ZoomImage 组合，并写入版本目录。ZoomImage 首先做长图/手势原型验证；无法满足时在 ImageSurface 接口后替换为 Telephoto。

参考：[Android 架构](https://developer.android.com/topic/architecture)、[Coil](https://coil-kt.github.io/coil/)、[ZoomImage](https://github.com/panpf/zoomimage)、[Jsoup](https://jsoup.org/)。

## 2. 建议工程结构

```text
app/                       导航、组装、应用入口
core/model/                SourceId、Comic、Chapter、PageRef、错误类型
core/network/              NetworkProfile、ClientFactory、Cookie、限流
core/database/             Room、DAO、迁移
core/storage/              凭据密文、偏好、文件目录
core/reader/               阅读状态、调度、图像处理接口
data/source/               ComicSource 接口、六个内置实现、DTO/Parser
data/repository/           作品、书架、历史、下载仓储
data/update/               GitHub Release、更新清单、APK 下载与校验
feature/discover/          发现与搜索
feature/detail/            详情与目录
feature/reader/            阅读 UI
feature/library/           收藏、历史、下载
feature/settings/          账号、网络、来源、外观
feature/auth/              受控 WebView、登录导航与界面状态
feature/update/            检查更新、下载进度、系统安装交互
```

初期可作为单 app 模块内的包结构；规模增长后拆 Gradle 模块。UI 不直接访问 OkHttp、网站选择器或数据库实体；来源适配器不持有 Activity。

## 3. 内容流

用户事件 → ViewModel → Repository → ComicSource → 网络/解析 → 标准模型 → UI。

页面图片另走统一 PageRepository：本地下载命中 → 已处理磁盘缓存 → resolvePage → 来源网络请求 → 特殊处理 → 磁盘文件 → 图片组件。

Reader 不接收永久有效的裸 URL 假设。它持有 PageRef，需要时解析可过期的 PageRequest。图片请求必须携带当前网络配置、来源身份、账号分区以及处理参数。

## 4. 内部接口示意

以下仅是设计合同，尚未编译。标识类型和结果类型在工程建立时补全。

```kotlin
interface ComicSource {
    val id: SourceId
    val capabilities: SourceCapabilities
    suspend fun discover(query: DiscoverQuery): PageResult<ComicSummary>
    suspend fun search(query: SearchQuery): PageResult<ComicSummary>
    suspend fun details(id: ComicId): ComicDetails
    suspend fun chapters(id: ComicId): List<Chapter>
    suspend fun pages(chapter: ChapterRef, cursor: Cursor?): PageResult<PageRef>
    suspend fun resolvePage(page: PageRef): PageRequest
}

interface SourceAuth {
    val supportedMethods: Set<AuthMethod>
    suspend fun authenticate(input: AuthInput): SessionStatus
    suspend fun validate(): SessionStatus
    suspend fun recover(reason: AuthFailure): RecoveryResult
    suspend fun logout()
}
```

认证与内容分接口；匿名来源无需提供虚假的 login 实现。可选能力使用显式 capability 标识；未支持操作返回 Unsupported，不能伪造空结果。

网页登录补充 `WebLoginSpec`（可信 origin、回调、所需 Cookie/存储键、验证方式）和 `WebLoginCoordinator`。来源只声明规则/验证合同，不持有 WebView/Activity；原生 UI 宿主管理 WebView，协调器管理 attempt 与取消。`SessionCandidate` 与正式会话分离，验证通过后再提交，Compose StateFlow 只接收进度和脱敏账号信息。[完整流程](06-网络登录与会话.md)

`UpdateRepository` 使用独立凭据作用域的更新客户端，继承 NetworkProfile；版本清单与下载任务绑定 Release/asset ID，按 longVersionCode 比较。GitHub Releases 为首版更新渠道，更新任务与漫画下载分离。[发布合同](11-应用更新与GitHub发布.md)

## 5. 标准错误

`NetworkUnavailable`、`Timeout`、`TlsFailure`、`AuthRequired`、`SessionExpired`、`ChallengeRequired`、`AccessDenied`、`QuotaExceeded`、`RateLimited(retryAfter)`、`NotFound`、`ParseChanged`、`UnsupportedFormat`、`StorageFull`。

网络返回非空不等于成功。每来源同时检查 HTTP 状态、Content-Type、业务码和必要字段。验证码 HTML、登录 HTML、403/429 不应被当作 JSON 解析失败。取消异常保持取消语义，不转成普通失败 Toast。

## 6. 开发规则

- 网络/磁盘/图片处理离开主线程；按来源限并发，取消与超时沿调用链传播。
- DTO、领域模型、Room 实体分开；签名测试注入时钟，不使用进程启动时的固定时间戳。
- URL 使用结构化 builder；密钥/账号只通过受限网络上下文注入，UI 状态不包含明文凭据。
- 不复制竞品的全局 Cookie 发送、明文日志或永久保存密码等行为；参考其协议过程，独立制定状态合同。
- 中文 Conventional Commits；功能、修复、文档分清；本轮不自动初始化 Git 或提交。
- Android 工程建立后运行单元测试、lint、Debug 构建，再做真机验证；当前 HTML 成功不代表 Android 构建成功。

## 设置与同步模块补充

类型化 DataStore 分别提供内容、来源、阅读、外观和应用偏好 Flow。ContentFilter 应用于浏览结果，ReaderPreferences 控制阅读生命周期；DataTransferService 校验/预览/事务导入，WebDavSyncService 管理差异、冲突和条件写入，独立凭据存储不复用来源认证。模块边界及验收见[设置规格](12-设置与偏好规格.md)。
