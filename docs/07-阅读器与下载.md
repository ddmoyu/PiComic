# 07 · 阅读器、缓存与下载

## 1. 实现边界

Compose Pager 负责分页，LazyColumn 负责连续布局，Coil 负责加载，ZoomImage 负责缩放与局部解码。阅读状态、预取调度、章节衔接、来源图片处理、离线任务由 PiComic 实现。单张长图阅读能力不等于整章连续阅读器。

参考：[Pager](https://developer.android.com/develop/ui/compose/layouts/pager)、[ZoomImage](https://github.com/panpf/zoomimage)、[Telephoto 分块解码](https://saket.github.io/telephoto/zoomableimage/sub-sampling/)。格式能否分块解码必须实测，不能承诺所有 AVIF/GIF 都有相同能力。

## 2. 三种阅读模式

| 模式 | 实现 | 进度 |
|---|---|---|
| 左到右 | HorizontalPager + ImageSurface | 稳定 pageId + 页码 |
| 右到左 | Pager 的阅读方向映射；页码仍递增 | 同上，不反转底层页面身份 |
| 纵向连续 | LazyColumn + 稳定宽高占位 + 长图可见区域处理 | pageId + 页内归一化位置 |

原图不能简单 `Crop` 成手机屏幕而丢失边缘文字。默认适应宽度/完整页面按模式选择；放大允许查看全部内容。章节末保留下一章入口；纵向模式另支持继续上拉换章，无下一章时仅给出轻量悬浮提示。

## 3. 手势仲裁

- 未放大：左右拖动用于翻页；轻点两侧前后翻，中部显示工具栏。
- 已放大：拖动优先平移图片；边界才把剩余位移传给翻页/列表。多指期间暂停翻页。
- 连续阅读缩放优先采用一致的视口手势，不让每张图片各自抢占垂直滚动；长图点击区域与拖动阈值分开。
- 双击缩放可关闭；开启时围绕点击点放大，第二次恢复；新页默认复位，跨页保持缩放作为后续设置。
- 旋转/进程重建依据内容坐标恢复，避免把旧屏幕的像素 offset 直接套用到新宽度。
- Android 系统返回优先关闭面板，再关闭工具层或退出阅读；退出持久化位置。

## 4. 图片处理与文件

`PageRef → resolvePage → authenticated request → raw temp file → source transform → atomic final file → ImageSurface`。

JM transform 在后台完成，处理前检查格式/是否已经还原。算法版本进入处理缓存键；失败不可把半成品当成功文件。大图重组先做内存预算，尽可能按条带/区域解码与写出；无法安全处理则限制并发并给出明确失败，不能同时全尺寸解码多张。

普通长图按缩放级别分块或切片显示，不将整章拼接为单张超大图。动画图与 AVIF 等平台差异使用独立解码能力检测；不支持则选择来源提供的兼容格式或提示，不能无限重试。

文件与缓存键：`sourceId / accountPartition / comicId / chapterId / pageId / quality / transformVersion`。URL 为可过期请求信息，不作为唯一书架、进度或下载身份。

## 5. 调度与限流

建议初值：当前页最高优先级，沿阅读顺序前向默认 3 张（可选 1–10 张）、后向最多一页预取；按网络和内存调整，EH/EX 可更保守。全局图片请求并发上限初始 4、单来源 2，JM 大图重组初始 1；这些是可调目标，需设备验证。

- 快速跳页取消远离窗口的预取；已完成文件可留缓存。
- 去重相同 PageRef 请求；阅读请求优先于后台下载；预取只缓存少量解码结果，其余留磁盘。
- 401/挑战等待认证；429 退避；配额不足暂停该来源任务；404 标记页失效；网络失败有限重试。
- URL 到期先重新 resolve 一次，再下载，不反复使用失效链接。

## 6. 缓存与下载区分

临时缓存使用 LRU 配额，建议默认 500 MB（十进制），可选 250/500/1000/2000 MB，可设置与清理；图片内存预算依据 heap 与设备内存能力，不硬编码“可无限缓存”。下载存独立目录，不能被 LRU 或“清理缓存”删除。

下载任务状态：`Queued → Resolving → Downloading → Processing → Completed`；可进入 `Paused / Failed / WaitingAuth / WaitingNetwork / Cancelled`。任务进度以已验证文件为准，不仅以内存计数为准。

- 每页写 `.part`，完整校验后原子重命名；下载清单记录格式、大小及可用 checksum。
- 服务端支持 Range 且资源校验器匹配才按字节断点续传，否则只重取该页；已完成页不重新下载。
- 应用退出/设备重启后从数据库恢复队列，遵守后台限制与用户意图；Wi-Fi 限定/移动网络设置明确。
- 用户主动长下载需要前台执行和可取消通知；WorkManager 用于可延后恢复/维护，不假设长任务永远免配额。Android 新版本前台服务类型、通知权限和任务配额在建工程时核对。[长时间后台任务](https://developer.android.com/develop/background-work/background-tasks/persistent/how-to/long-running)
- 下载完整后飞行模式验证；删除指定章节同时更新数据库与文件，失败可重试，不静默留下“已删除”假状态。

## 7. 阅读验收样本

普通 JPEG/PNG、WebP、AVIF（支持/不支持两类设备）、GIF、超宽双页、超长图、100+ 页章节、混合尺寸、断网重试、链接过期、JM 余数条带、反复翻页/缩放、边读边下载、旋转与进程死亡。所有结果分为模拟器、真机、真实平台三类记录。

## 阅读偏好补充

增加音量键翻页、自动翻页间隔、前台常亮、1–10 张预加载、双击/长按缩放。自动翻页由阅读器手动启动、章末停止，拖动/缩放/面板暂停，退出或后台停止；连续长图正式版按视口推进。下载并行默认 3 个章节任务（1–6），不突破来源/解码并发上限。常亮、音量键与显示模式随页面生命周期释放，详细默认值和真机验证见[设置规格](12-设置与偏好规格.md)。

### 连续阅读图片衔接

纵向连续模式中，图片之间不显示页码、标题、分隔线或额外间距，图片以 block 布局无缝衔接。页码和进度只显示在可隐藏的阅读工具栏；隐藏工具栏后不保留浮动页码。保留图片原有内容与边缘，不自动裁掉原图留白；章节页序、进度记录和跳页功能保持可用。原生 LazyColumn 的 item 间距为 0 dp。

### 纵向章末衔接与桌面原型手势

1. 区分正常滚动与边界之外的继续上拉；正常滚动消耗完毕后，后续位移才累计到换章手势，避免快速滚动直接跳章。
2. HTML 原型使用统一 Pointer Events 路径处理鼠标拖拽及单指触屏滚动，以指针捕获保证拖出画面后仍能结束手势；浏览器滚轮保持普通滚动，章末才进入累积反馈。
3. 当前原型累计上拉 180 CSS px 达到阈值；页尾位移采用递减响应的阻尼曲线，上限 112 px，底部逐渐露出下一章画面。松开后下一章画面用约 640 ms 自底部上移接替当前画面，文字保持紧凑灰色提示。滚轮位移按 0.28 倍累计、单次上限 28 px，并要求至少 6 次向下事件、持续意图不少于 500 ms；静止 260 ms 后确认。少量大幅滚轮事件也不能绕过阈值。以上为原型调校值，Android 实现需按 dp 与真机手感调整。
4. 转场期间禁止重复换章；跨章保留滚轮输入保护，新章节首屏拦截残余滚轮输入，持续 700 ms 没有滚轮事件后才接受新一轮滚动；进入下一章时恢复第 1 页并保存阅读进度。返回、切换模式、取消手势时清理定时器、指针捕获和动画；面板打开后不得执行待处理换章。
5. 自动翻页仍在本章结束时停止。手动上拉换章与自动翻页分开，启动手动换章时停止自动翻页。
6. 原型用示意图固有宽高预留懒加载空间，避免图片载入后改变章末位置。原生实现使用页面元数据并验证真实长图、惯性滚动、多指缩放和弱网加载；HTML 手势通过不代表原生阅读性能验收。
