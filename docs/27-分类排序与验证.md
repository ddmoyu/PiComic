# 分类结果页的来源排序

2026-09-20。只修改点击分类后进入的作品列表；分类选择页继续使用原来的标签布局。

## 来源能力与参数

| 来源 | 排序 | 原生请求 |
| --- | --- | --- |
| JM | 最新、总排行、月排行、周排行、日排行、最多图片、最多喜欢 | `o=mr/mv/mv_m/mv_w/mv_t/mp/tf`，分类走 `categories/filter`，标签走 `search` |
| 哔咔 | 最新、最早、最多喜欢、最多浏览 | `/comics?s=dd/da/ld/vd&c=分类` |
| nhentai | 最新、总排行、月排行、周排行、日排行 | `sort=date/popular/popular-month/popular-week/popular-today`；类型分类走 `/api/v2/search`，语言分类走 `/api/v2/galleries/tagged` |
| Hitomi | 最新收录、最新发布、日/周/月/年排行、随机 | 类型及语言对应的 Nozomi 索引，按索引原有顺序读取；随机按官网方式打乱分类索引并缓存，翻页保持同一顺序 |
| EH/EX、绅士漫画 | 最新 | 分类原生时间顺序；官网独立的全站热门/收藏排行不冒充当前分类排序 |

## 核对证据

- JM 七个 `o` 参数均通过匿名真实接口检查，响应 `code=200`、每项返回 80 条记录，七项有不同的 ID 序列摘要。月/周/日结果总数分别为 3492/1008/92；总数会随平台内容变化。只记录数量、状态和摘要，不输出标题、封面或凭据。参数也与 [Venera JM 接入源码](https://github.com/venera-app/venera-configs/blob/main/jm.js) 的 `categoryComics` 一致。
- 哔咔沿用已有来源契约 `dd/da/ld/vd`，与 [PicaComic 请求实现](https://github.com/wgh136/PicaComic/blob/155cf0c6d7018f9521f8c375b142bafd85e47a4d/lib/network/picacg_network/methods.dart) 的分类请求一致；本次没有重新登录真实账号。
- nhentai 直接读取 [官方 OpenAPI](https://nhentai.net/api/v2/openapi.json)，上述两个分类端点均声明这五个 `sort` 值；`/galleries` 本身不声明排序参数。
- Hitomi 后台读取主页的 `orderbydropdown` 和官方 `search.js` 的 `nozomi_address_from_state`。类型的周排行、发布时间和中文目录的月排行、发布时间索引均返回 HTTP 206；每次只取 4 字节，不下载图片。
- 绅士漫画后台读取当前分类导航和表单：分类仍为 `albums-index-cate-…`，全站收藏排行另在 `albums-favorite_ranking.html`。EH [搜索说明](https://ehwiki.org/wiki/Gallery_Searching) 明确按最近/最早作品导航，最低评分属于筛选条件，不是评分排序。

## 交互和验证

分类结果顶部显示可换行的排序按钮，选中状态高亮。切换时保留分类、清空旧结果、回到第一页与列表顶部；分页沿用排序，过时请求不能追加。进入详情再返回或恢复保存状态后保留排序与列表位置。各来源不再套用哔咔的默认排序偏好。

专项验证使用合成 API 响应、占位封面和无窗口 Android 36.1 模拟器：检查 JM 七种分类及标签参数、哔咔四种排序、nhentai 类型/语言参数、Hitomi 类型/语言索引与 Range、随机跨页稳定性，以及排序切换、分页、状态恢复、分类入口布局。控制器测试覆盖旧请求晚到、游标重置与分页保留。

已通过 5 项来源契约测试、2 项分类 UI 测试和 5 项列表控制器单元测试，共 12 项。调试编译与 `git diff --check` 通过，记录位于 Git 忽略的 `artifacts/category-sort-*`。页面恢复测试发现并修复了同时等待未显示网格布局的问题，最终只重置正在使用的列表或网格。
