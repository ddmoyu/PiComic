## 4. 工程验证层次

- 单元/夹具：签名时钟、JSON/HTML 解析、JM 图像排列、分页、错误分类、Cookie 匹配、会话 single-flight、进度映射。
- 网络集成：MockWebServer 覆盖 401/403/429/重定向/断流；真实来源样本仅作为额外联调，不让 CI 持续刷站。
- Android UI：主要导航、返回栈、登录表单、阅读跳页、下载状态；快照只用于稳定布局，不硬编码网络内容。
- 构建：建工程后执行 `testDebugUnitTest`、`lintDebug`、`assembleDebug`；正式包另验 R8 后真实图片处理/登录回调。
- 设备：API 26 与当前目标系统，至少一台实体手机；360/390/430 dp、横屏、600/800 dp、大字体、深色、分屏。
- 原型：浏览器交互与截图只证明 HTML 行为，不代替以上 Android/平台检查。

## 5. 主要风险及处理

| 风险 | 处理/退出条件 |
|---|---|
| 协议漂移或参考实现冲突 | profile 明确版本；联调失败时标未接入，不猜测成功 |
| 域名更换与登录主机变化 | 候选与信任范围分开，匿名探测后再发送凭据 |
| 网页验证无法在 WebView 完成 | 明确告知限制，平台支持的回调或手动导入；不承诺万能解决 |
| 图片额度/429 | 源级暂停和退避，低预取，不不断换地址重试 |
| 长图/JM 重组内存峰值 | 单任务处理、尺寸预算、区域/条带处理、真机压力测试 |
| 平板/旋转布局 | 约束宽度与自适应网格、进度恢复，不额外扩展功能范围 |

## 6. 实现前的评审项

确认 HTML 的导航与阅读交互；确认首版 P0/P1 范围；确定包名/最低系统及 GitHub 发布仓库、正式签名。发布渠道采用 GitHub Releases，按[更新规范](11-应用更新与GitHub发布.md)落地。认证和网络方案按本稿推进技术验证，待真实平台证据再冻结具体地址和协议 profile。
