# 分类目录修复与验证

2026-09-20。范围为补齐各平台分类列表，不新增「所有分类」入口。

## 问题与修复

JM 的 `/categories` 正常返回目录，但首项使用 `id=0`、`slug=""`。旧解析器要求所有 slug 非空，导致发现页可以读取内容，分类页却整体失败。现仅对这个官方默认目录使用筛选值 `0`，其他无效 slug 仍报结构错误。

JM 同名子目录过去以名称作为同一个 map 键，可能覆盖其他父目录下的路线。现使用「父目录 / 子目录」保留独立映射，并接入接口返回的标签分组；目录走 `categories/filter`，标签走 `search`。

公开固定分类目录直接读取公共元数据，避免已保存账号的过期状态阻止目录显示。实际内容请求仍执行原有登录与权限检查。哔咔分类继续走认证 API，不用虚构目录代替登录失败。

## 验证方式

仅进行后台 HTTP 元数据检查与无窗口 Android 测试，不打开网站、不显示图片、不截图。真实请求只记录状态、数量和接口结构，不输出作品内容或凭据。

- JM：真实 Android 适配器读取目录，校验 81 项且无重复键；回归覆盖空 slug、同名子分类、标签搜索参数。
- 绅士漫画：后台读取官网导航，目录编号与全部 19 个筛选请求一一对应。
- Hitomi：6 个真实类型索引均返回 HTTP 206；每次只读取 4 字节索引样本，不下载图片。
- nhentai：两种类型的匿名筛选 API 均返回有效分页结果；分类与语言分别验证搜索参数、tag_id。
- 哔咔：用 70 个合成分类验证无截断及外部网页过滤，未声称完成真实账号登录验证。
- UI：合成数据验证六个平台切换、滚动到底部、点击回调来源正确，且不存在「所有分类」入口。

功能验证通过：Android 36 上完成 46 项离线来源/UI 检查及 1 项 JM 目录实测；Android 26 上完成 9 项分类专项检查。这些检查已在调整开发节奏前执行，后续日常功能开发不重复旧安卓测试。

验证日志保存在 Git 忽略的 `artifacts/` 下。本轮只提交分类修复，不创建发布标签，不触发 GitHub Actions 发版。后续开发仅测试当前功能；收到明确发包指令时，再集中执行较完整的回归和发布验证。
