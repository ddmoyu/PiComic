# 17 · 哔咔账号登录联调

日期：2026-09-20。开发版本：`0.2.3-alpha` / `versionCode 7`。

## 本轮范围

在既有网络、Keystore 和 SessionCoordinator 基础上接入首个来源的原生认证流程。入口为「设置 → 账号管理 → picacg」。不保存密码；不从网页 Cookie 推导 API Token；不把当前本地示例目录标为真实内容。

- 固定 HTTPS origin `https://picaapi.picacomic.com:443`，协议 profile 为 `picacg-2.2.1.3.3.4-v1`。
- 提交密码前先匿名调用 `GET users/profile`，要求 HTTP 401 及 `code=401/error=1005/message=unauthorized` 的结构；网页、跳转或不匹配响应均阻止后续登录。
- `POST auth/sign-in` 返回令牌后，携带令牌调用 `GET users/profile`；要求成功信封、用户 ID 和有效显示名，才提交至 AES-GCM 加密会话文件。
- 启动及手动验证已保存会话，共用一个在途任务。401 表示失效并清除该来源令牌；断网保留密文，状态为待验证。没有已验证的 refresh 协议，因此不自动重放密码登录。
- 错误密码、403、429、5xx、重定向和格式不符分别提示；登录 POST 不重试，错误提示不回显响应正文。
- 登录、验证和连接测试使用同一网络 generation；换网取消旧请求。离开登录页、退后台或主动取消后，旧回调不能恢复账号。重新登录失败保留原有会话。
- 账号、密码使用页面内存，不进入保存状态、普通偏好或备份。提交后清空密码框，任务结束清零口令数组。仅发布账号显示名和状态；其他来源独立。

## 自动验证

- JVM：独立 HMAC 固定向量、土耳其区域设置、编码 query/method；登录验证后持久化、失败替换保留旧会话、过期清理、未就绪网络不发密码、换网与退出竞态、并发恢复合并。
- Android API 36 模拟器：MockWebServer 真实 HTTP 契约，401/400/403/429/503、异常字段、重定向不携带密码/Token、慢响应取消、旧客户端拒绝请求、有界响应体。
- Compose：错误登录 → 成功验证 → 清除会话；退出页面清空输入并取消旧任务。夹具账号只在测试中存在。
- 默认回归不访问漫画平台。`PicacgLiveProbeTest` 仅在显式传入 `liveSourceProbe=true` 时运行匿名联调；其代理地址是模拟器专用，未写入应用偏好。
